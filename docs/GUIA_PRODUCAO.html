1 Posso apagar os arquivos .zip?

Sim, com uma ressalva. O dashboard não precisa dos zips para funcionar: ele lê apenas data_bilheteria.csv e data_ranking.csv (11 MB no total). Os zips só servem para refazer o pipeline do zero.

ArquivoTamanhoPara que serveApagar?
bilheteria-…-distribuidoras-csv.zip
bilheteria-…-exibidoras-csv.zip		1,7 GBOriginais da ANCINE; recriam tudo desde o inícioPode, se tiver backup
dados/bilheteria_unificada.csv.gz1,8 GBCSV unificado (entregável da etapa 2); gera os agregados do dashboardMantenha
dados/staging/*.parquet0,5 GBCópia intermediária; só é usada para refazer o perfil e a unificaçãoPode
.venv/0,3 GBAmbiente Python local; recriável com uvPode (recria)
projeto_completo/11 MBO dashboardMantenha
RecomendaçãoAntes de apagar, mova os zips para um disco externo ou para a nuvem (Google Drive, iCloud). Eles são os únicos arquivos que permitem refazer o perfil e a unificação. O CSV unificado regenera os agregados do dashboard, mas não refaz o perfil dos arquivos originais.

Se apagar sem backup, os mesmos conjuntos ("bilheteria diária de obras por distribuidoras" e "por exibidoras") podem ser baixados de novo no portal de dados abertos da ANCINE, já em versão atualizada.

2 O que vai para produção

Apenas a pasta projeto_completo/. Ela é pequena, autossuficiente e já tem o Procfile e o requirements.txt.

BilheteriaDash/
├── projeto_completo/        ← o que roda no servidor (11 MB)
│   ├── app.py               instância Dash; expõe server para o gunicorn
│   ├── index.py             layout + callbacks
│   ├── assets/styles.css
│   ├── data_bilheteria.csv  10 MB
│   ├── data_ranking.csv     1,5 MB
│   ├── requirements.txt
│   └── Procfile
├── pipeline/  schema.sql  *.md   ← vão para o GitHub (documentação/portfólio)
└── dados/  .venv/                ← NÃO vão para o GitHub (grandes/recriáveis)
Testado localmentegunicorn index:server sobe sem erro e responde HTTP 200. Cada worker usa de 230 a 350 MB de RAM (no início e depois de uso), o que define a configuração dos planos gratuitos (passo 5).

3 Preparar o projeto

Já feito neste projetoOs passos 3.1 a 3.4 já foram aplicados: .gitignore, projeto_completo/.python-version, o Procfile abaixo e o app.title. O comando do Procfile foi testado com gunicorn, com fonte, tema e Play funcionando. O conteúdo fica aqui como referência.

3.1 Criar o .gitignore em BilheteriaDash/

O GitHub recusa arquivos acima de 100 MB, e o CSV unificado tem 1,8 GB. Ele precisa ficar fora do repositório.

.venv/

extraido/

3.2 Fixar a versão do Python

Crie projeto_completo/.python-version. O projeto foi testado em Python 3.12, e as hospedagens leem esse arquivo para escolher a versão.

3.12

3.3 Ajustar o Procfile para pouca memória

Um worker com várias threads cabe nos 512 MB dos planos gratuitos. Dois workers (até cerca de 700 MB) passam do limite.

web: gunicorn index:server --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120

3.4 (Opcional) Título da aba do navegador

Hoje a aba mostra "Dash". Em app.py, logo depois de criar o app:

app.title = "Bilheteria Diária – Brasil"

3.5 Testar como em produção

cd BilheteriaDash/projeto_completo
PORT=8050 ../.venv/bin/gunicorn index:server --bind 0.0.0.0:8050 --workers 1 --threads 4

Abra http://127.0.0.1:8050. Se tudo carregar, o servidor de produção também vai carregar.

4 Publicar no GitHub

Você já tem git e gh instalados. Com o .gitignore do passo 3.1 criado:

cd BilheteriaDash
git init
git add .
git status            # confira: dados/ e .venv/ NÃO podem aparecer
git commit -m "Dashboard de bilheteria diária (ANCINE)"
gh repo create bilheteria-dash --public --source=. --push
Confira antes do pushRode git status e verifique se nenhum arquivo maior que 100 MB foi incluído. Se o .csv.gz aparecer, o .gitignore não está na pasta certa.

5 Deploy no Render (recomendado)

O Render roda o Procfile e o requirements.txt sem configuração extra, é uma alternativa ao Heroku e tem plano gratuito.

  1. Crie uma conta em render.com e conecte o GitHub.
  2. New → Web Service e escolha o repositório bilheteria-dash.
  3. Preencha:
    Root Directoryprojeto_completo
    RuntimePython 3
    Build Commandpip install -r requirements.txt
    Start Commandgunicorn index:server --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120
    Instance TypeFree (512 MB) para demonstração; Starter para uso contínuo
  4. Clique em Create Web Service. O primeiro build leva de 3 a 5 minutos. No fim, o painel mostra uma URL do tipo https://bilheteria-dash.onrender.com.
Plano gratuito "dorme"Depois de cerca de 15 minutos sem acesso, o serviço é suspenso, e o próximo acesso leva perto de 1 minuto para acordar. Para uma apresentação, abra o link alguns minutos antes. Para uso contínuo, use um plano pago.

A cada git push na branch principal, o Render refaz o deploy sozinho.

Dockerfile (para Hugging Face, VPS ou qualquer nuvem com contêiner)

Salve como projeto_completo/Dockerfile:

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
ENV PORT=7860
EXPOSE 7860
CMD gunicorn index:server --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120
cd BilheteriaDash/projeto_completo
docker build -t bilheteria-dash .
docker run --rm -p 7860:7860 bilheteria-dash

7 Exibição rápida, sem deploy

Para mostrar o dashboard numa reunião ou aula, sem hospedar:

No seu computador

cd BilheteriaDash/projeto_completo
../.venv/bin/python index.py

Abra http://127.0.0.1:8050 e use o navegador em tela cheia. Para o modo apresentação, dá para alternar o tema e usar o botão Play.

Link temporário para outras pessoas

Com o dashboard rodando, um túnel cria uma URL pública provisória, que vale enquanto o comando estiver aberto:

brew install cloudflared
cloudflared tunnel --url http://127.0.0.1:8050
AtençãoQuem tiver o link acessa o seu computador por essa porta enquanto o túnel estiver ativo. Os dados são públicos, mas encerre o túnel (Ctrl+C) ao terminar.

8 Atualizar os dados

A ANCINE atualiza os conjuntos com frequência (os arquivos atuais vão até setembro e outubro de 2026). Para atualizar o dashboard:

  1. Baixe os dois zips novos no portal de dados abertos da ANCINE e salve-os na pasta acima de BilheteriaDash/.
  2. Garanta cerca de 16 GB livres em disco (para a extração temporária).
  3. Rode o pipeline, que leva perto de 10 minutos: 
    cd BilheteriaDash
rm -rf extraido dados/staging
mkdir -p extraido/distribuidoras extraido/exibidoras
unzip -q ../bilheteria-diaria-obras-por-distribuidoras-csv.zip -d extraido/distribuidoras
unzip -q ../bilheteria-diaria-obras-por-exibidoras-csv.zip -d extraido/exibidoras
.venv/bin/python -I pipeline/perfil.py extraido dados/staging - dados/perfil.json
.venv/bin/python -I pipeline/unificar.py dados/staging dados/perfil.json dados/bilheteria_unificada.csv.gz dados/reconciliacao.json
.venv/bin/python -I pipeline/agregar_dashboard.py dados/bilheteria_unificada.csv.gz projeto_completo
rm -rf extraido
  4. Confira em dados/reconciliacao.json se antes é igual a depois nas duas fontes.
  5. Publique: o Render refaz o deploy sozinho. 
    git add projeto_completo/data_bilheteria.csv projeto_completo/data_ranking.csv
git commit -m "Atualiza dados da ANCINE"
git push

Os anos do RangeSlider e os filtros se ajustam sozinhos aos dados novos, porque são lidos do CSV.
